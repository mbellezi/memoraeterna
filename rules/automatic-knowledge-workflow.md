# Installed automatic knowledge workflow

This is the current successor specification for automatic knowledge operation.
Historical versioned records retain their own evidence and replay contracts.

- Initialize stable Wiki areas and entity navigation categories idempotently with
  stable IDs. Atomic notes, Sources and Attachments have separate native browsing.
  The initial upgrade places existing roots through normal page revisions and
  preserves IDs, evidence, human sections and all historical revisions. Later
  startups do not repeat placement or overwrite human changes.
- Install a primary whole-library policy, including future inputs and explicit
  exclusions, with incremental/daily/weekly/monthly enabled routines. Preserve
  existing model overrides and optional interpretation/evolution grants. Missing
  model/profile/routing configuration is visible readiness, not a setup wizard.
  Initial integration is ordinary due coverage work.
- Knowledge automation owns overview, tasks, source journeys, schedules, decisions
  and operational configuration. Wiki reading has no title-driven generation or
  automation-setup button. Harness/domain controls belong to automation; shared
  prompt editing is embedded as a subpage using the same canonical prompt catalog.
- Show scheduled, queued, deferred, budget-blocked, failed, review and historical
  work using paginated canonical reads. Ingestion completion, Wiki coverage and
  Obsidian delivery are independent. A recent-history window cannot hide older
  pending work. Keep retired routine records and retained proposals inspectable.
- Saving operational configuration performs validated revision/activation
  internally. Preserve scope checks, evidence validation and immutable admitted
  inputs. Retire new legacy routine admissions during setup; historical runs and
  reviews keep their versioned readers without a second routine-creation UI.
- Before new curator work, plan synthesis, support assessment and a bounded repair
  cycle against occurrence and parent-month capacity. Reduce whole-original groups
  before admission when possible. Planning is conservative and separate from
  measured usage; actual calls retain transactional reservations and authority.
- Missing-model schedules retain their due date and record the prerequisite.
  Pin the configured profile only on actual admission. Automatically recheck
  temporary admission blockers. Never replay uncertain provider calls, canceled
  work or rejected semantic decisions, or reset spent budgets through retry.
- Obsidian mirrors canonical changes and initial configuration when configured,
  enabled and unpaused. New ingestion has no projection checkbox or AI prerequisite
  for mirroring originals. Pending/conflicting delivery is visible independently.
  Stable native area IDs map to portable area indexes. Registered paths, preserved
  editor changes and reviewed physical migrations remain authoritative.
- Each UI change covers loading, empty, error, waiting, partial and success states.
  Use the shared visual tokens, descriptive localized labels and contextual actions.

- Outward Obsidian conflicts do not globally block automatic knowledge work.
  Canonical revision guards remain in force; projection conflicts retain their
  separate pending decisions and protected local bytes.
- Coalesce input deliveries by policy and exact source scope for the task overview,
  with a pending-change count and paginated drill-down retaining every event.

- Serialize unfinished automatic curator admission per policy, retaining generation
  deduplication under the same lock. Waiting for another group is temporary
  deferral, not a semantic failure or a human-review requirement. Recompute the
  complete-unit capacity after the previous group settles.

- The automation Budget subpage exposes the shared UTC monthly calls/token ceiling,
  existing reservations and remaining capacity, and every bounded curator-group
  limit. Routine limits remain editable from Schedules with a Budget shortcut.
  Validate numeric ranges and the complete synthesis/support/repair call allowance
  before saving. Preserve current values until an explicit save.
- Monthly ceiling edits atomically compare every active schedule revision under
  the same policy lock as reservations and update all active routine bindings.
  Every future reservation and capacity check uses that live shared ceiling,
  including admitted occurrences. Preserve occurrence limits, admitted snapshots,
  recorded or uncertain reservations, pause state and historical failures. Lowering
  a ceiling below reserved usage blocks new calls without refunding prior usage.
  New scope bindings inherit the shared ceiling; stale previews cannot reset it.
- Curator-limit edits use the normal validated policy revision/activation flow,
  disclose revocation of earlier work and retain paused state and history. Range
  bounds remain backend-owned; no UI control grants unbounded work or unknown
  monetary spend.

- Display human review only when the linked analysis has an actionable proposal.
  Exhausted structural/source-faithfulness validation is a terminal automatic
  rejection, with its own provenance rather than a human decision. Reconcile older
  failed analyses and their non-actionable waiting occurrences through the exact
  child, bootstrap and delivery links. Preserve canceled occurrences, proposals,
  originals, diagnostics, audits and budgets. Terminal negative delivery receipts
  are outcomes, not successful integration or requests for human approval.
  Other technical failures retain their distinct cause and uncertain-call guards.
  Show the bounded diagnostics and a direct analysis/review action.
- A shared Clear task history action covers processing and automatic knowledge.
  It removes terminal entries from display through the existing job dismissal and
  a persisted cutoff, never through deletion of execution records, proposals,
  evidence, uncertainty, usage or budget ledgers. Current pending deliveries,
  blocked/review work and schedules remain visible; superseded-policy deliveries
  are historical entries. Exact result/receipt lookups remain available after
  cleanup, and later completions are not covered by an earlier cutoff.

- Check retained decisions before admitting automatic or manual occurrences.
  Canceling, cleaning display history, editing routine allowances and advancing
  calendar/month periods cannot create empty wrappers for unchanged rejected
  inputs. Current schedules disclose the retained outcome and wait for new inputs;
  genuine actionable proposals keep their review action. New input generations or
  activated policy revisions can permit new inspection, without replaying the
  previous analysis or refunding its reservations.
- Persist validation feedback in the existing rejected run/checkpoint and proposal
  owners, including rejection time, exact input fingerprint, original revision
  identities and bounded diagnostics/affected draft text. Future curator snapshots
  may admit at most four such records, two issues per record, 800 characters per
  rejected excerpt and 6,000 serialized characters total. The entire historical
  source scope must fit the new admitted sources; excluded-source prose must never
  enter this context. Keep original hashes and IDs inspectable in the UI.
- Feedback is explicitly historical context, never current source evidence,
  a global rule or permission to mutate knowledge. Recheck current originals using
  the normal complete support gate. Pin admitted feedback for audit/replay and
  include it in context/budget planning. Registering feedback creates no impact
  event and is excluded from input identity, so it cannot trigger its own retry.
  Technical failures and uncertain calls do not create content lessons.

- Reset everything awaits the same default initialization as application startup
  before reporting success or resuming workers. Restore the Wiki areas, primary
  policy and four enabled routines even without a configured model, and reload
  the prompt runtime so deleted overrides cannot survive in memory.
