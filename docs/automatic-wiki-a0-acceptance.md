# Automatic wiki acceptance ownership matrix

This is A0's executable acceptance design, not downstream test completion.
The machine-readable source inputs, proposal, variable cases and path map live in
[scripts/fixtures/automatic-wiki](../scripts/fixtures/automatic-wiki). The A0 suites
parse real Zod contracts, exercise rejection cases, freeze real current prompt
outputs and check fixture invariants. They never simulate a passing A2–A8 product.

Owners below are existing implementation boundaries. Test names prefixed with
`automatic-wiki-*` designate required successor suites/verifiers; they must be
implemented in the named milestone. Existing baseline tests/scripts remain
regression foundations. A failure or missing real-model/native/PG artifact at a
later gate remains pending even if every A0 test passes.

A0 assertions are executable in `automatic-wiki.test.ts`, `prompt-catalog.test.ts`
and `automatic-wiki-prompts.test.ts`. They include negative references, exact
assessment states, proposal limits, conservative backfills, per-consumer receipts,
calendar invariants, shared note identity, path-map collisions and template-oracle
integrity. Every row above remains a required downstream acceptance scenario;
none is satisfied merely by the existence of its documentation row.
