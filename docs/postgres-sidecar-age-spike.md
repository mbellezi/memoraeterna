# Postgres Sidecar Spike: pgvector and Apache AGE

This document records the reproducible validation path for Phase 1, Step 0.5.

## Target

- PostgreSQL sidecar: `18.4`
- pgvector: `0.8.4`
- Apache AGE: `PG18/v1.7.0-rc0`
- First validated platform: macOS

## Inputs

The development sidecar is installed with:

```bash
npm run sidecar:install:postgres
```

The installer:

- runs `scripts/setup-dev-env.mjs`, creating random local database credentials in `.env` and `apps/desktop/.env` when needed;
- downloads the PostgreSQL `18.4` macOS binary zip linked from the official PostgreSQL macOS download page and hosted by EDB;
- extracts it to `vendor/sidecars/postgres/darwin-{arch}/postgresql-18.4`;
- builds and installs pgvector `0.8.4`;
- builds and installs Apache AGE `PG18/v1.7.0-rc0`;
- writes a local `memora-sidecar.json` manifest with archive checksum and install paths.

Production packaging must copy the installed sidecar under the app resources directory:

```txt
resources/
  sidecars/
    postgres/
      darwin-arm64/
        postgresql-18.4/
```

At runtime the resolver checks, in order:

- `MEMORA_POSTGRES_SIDECAR_ROOT`;
- `MEMORA_POSTGRES_BIN_DIR`;
- `resourcesPath/sidecars/...` in packaged Electron;
- `vendor/sidecars/...` in development.

## Desktop Runtime Lifecycle

The Electron main process owns the runtime database lifecycle:

- credentials are generated per installation and stored under Electron `safeStorage`;
- the data directory lives under `app.getPath("userData")/database/postgres-data`;
- the sidecar starts on loopback, trying `MEMORA_DATABASE_PORT` first and falling
  back with a warning to a free dynamic port when needed;
- the renderer only receives validated lifecycle status through preload IPC;
- the first renderer screen waits with a bootstrap spinner until the database status is `ready`;
- Drizzle migrations run after PostgreSQL is ready and before the shell is released;
- app shutdown waits for the settings repository, Postgres pool, and sidecar process to stop.

Development `.env` files are still generated by `scripts/setup-dev-env.mjs` for CLI workflows and local scripts. The packaged app runtime does not rely on those fixed credentials; it uses the per-installation safeStorage credentials and the sidecar under the app resources directory.

Packaged builds must also copy the Drizzle migrations to:

```txt
resources/
  drizzle/
```

## What The Script Verifies

The script in `scripts/postgres-sidecar-spike.ts`:

- creates a temporary data directory;
- runs `initdb` with `scram-sha-256`;
- starts PostgreSQL on loopback with a dynamic port;
- creates a test database;
- runs `CREATE EXTENSION vector`;
- runs `CREATE EXTENSION age`;
- executes a trivial AGE Cypher query;
- executes a trivial pgvector distance query;
- stops and restarts the server;
- reports cold start and restart timings;
- removes the temporary data directory.

## AGE Build Notes

The macOS AGE build is automated by `scripts/install-postgres-sidecar.mjs`. It passes the sidecar `PG_CONFIG`, the current macOS SDK path, and system Perl because the EDB PGXS metadata can point at build-machine paths that are not present on developer machines.

The manual equivalent is:

```bash
make \
  PG_CONFIG=/absolute/path/to/postgres/bin/pg_config \
  PG_SYSROOT="$(xcrun --show-sdk-path)" \
  PERL=/usr/bin/perl
make install \
  PG_CONFIG=/absolute/path/to/postgres/bin/pg_config \
  PG_SYSROOT="$(xcrun --show-sdk-path)" \
  PERL=/usr/bin/perl
```

## Current Validation Status

Validated on macOS arm64 with:

```bash
npm run sidecar:install:postgres
npm run sidecar:spike
```


## Remaining Risks

- Windows and Linux AGE builds are explicitly out of scope for the first spike and remain pending.
- AGE is an `rc0` target; product graph queries must keep relational fallbacks.
- Native artifacts need signing/notarization before application packaging.
- The packaging config still needs to copy `resources/sidecars/...` and `resources/drizzle/`.
- Major PostgreSQL upgrades require an explicit data migration plan.
